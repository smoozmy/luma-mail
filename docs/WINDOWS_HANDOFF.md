# Posta: установка на Windows 11 и продолжение работы в Codex

Подготовлено **22 октября 2026**, исходная версия **0.2.0**.

Это инструкция и передача контекста для нового Codex на ПК. Старая переписка для начала работы не требуется: необходимые сведения включены в исходники и этот файл.

## 1. Что перенести с Mac

На рабочем столе Mac подготовлены:

- `Posta-Windows-Transfer-2026-10-22.zip` — весь комплект одним архивом;
- папка `Posta-Windows-Transfer-2026-10-22` — тот же комплект уже распакован;
- `Posta-Windows-Codex-START.md` — эта инструкция отдельно.

Внутри комплекта:

```text
Posta-Windows-Transfer-2026-10-22/
  Posta-Windows-Codex-START.md
  Posta Setup 0.2.0.exe
  Posta-source-0.2.0-2026-10-22.zip
  SHA256SUMS.txt
```

Перенеси ZIP или всю папку на ПК через флешку, локальную сеть либо свой облачный диск. Рекомендуемое место на ПК — `Загрузки`. Распакуй общий архив через Проводник → «Извлечь всё».

Комплект содержит исходники и установщик. В нём нет `node_modules`, личной почты, паролей, `.env`, SSH-ключей, production-конфигурации LumaHub и истории Git. Не нужно переносить всю папку LumaHub или весь каталог `.codex` с Mac.

## 2. Как просто установить и пользоваться Posta

1. Открой `Posta Setup 0.2.0.exe` на Windows 11 **x64**.
2. Пройди установщик и запусти Posta через «Пуск» или ярлык.
3. Нажми «Добавить учётную запись» и подключи свои ящики. До подключения слева не должно быть чужих или демонстрационных аккаунтов.
4. Пароли вводи только в приложении; в чат Codex их не отправляй.

Для запуска установленной Posta Node.js, npm и Git не нужны. Они понадобятся только для разработки. Установщик личный, без сертификата издателя; если Windows ограничивает запуск, сверяй происхождение и контрольную сумму, а не отключай системную защиту целиком.

Если Posta уже установлена, полностью заверши старую версию через значок в трее → «Завершить», затем установи 0.2.0 поверх. Локальные аккаунты и кэш хранятся отдельно от установки. Windows ARM64 в этой передаче отдельно не проверялась.

### Почтовые подключения

- **iCloud:** адрес iCloud и пароль приложения из настроек Аккаунта Apple.
- **Gmail:** пароль приложения Google при доступной двухэтапной аутентификации. Google OAuth в 0.2.0 не реализован; рабочая политика Google может запрещать пароли приложений.
- **Яндекс:** разрешить IMAP в настройках почты и создать пароль приложения типа «Почта» в Яндекс ID.
- **Microsoft 365 / Outlook.com:** облачный сценарий через OAuth, собственный client ID и разрешения IMAP/SMTP; полная инструкция находится в `Posta/README.md` внутри исходников.
- **Корпоративный Exchange:** пока **не реализован**, см. раздел 8. Не выбирай облачный Microsoft 365 в расчёте, что это автоматически подключит любой корпоративный Exchange.

Пароли приложений, аккаунты и кэш с Mac переносить не нужно. Ключи шифрования привязаны к ОС/пользователю; на ПК подключи ящики заново. Уже полученная серверная почта загрузится с серверов. Локальные несинхронизируемые черновики — отдельные данные, их этот комплект не переносит.

## 3. Установить Codex и инструменты на ПК

### Codex

Используй актуальную [официальную инструкцию OpenAI для Windows](https://learn.chatgpt.com/docs/windows/windows-app). В ней Windows-приложение с Codex сейчас называется ChatGPT desktop app. Установи приложение по ссылке из документации и войди в свой аккаунт ChatGPT. При первом запуске заверши предложенную настройку Windows.

Вариант установки из PowerShell, приведённый в официальной документации:

```powershell
winget install --id 9PLM9XGG6VKS --source msstore
```

Для этого проекта выбираем агент **Windows native** и терминал **PowerShell**. WSL не требуется: проверять Windows-интерфейс и собирать установщик удобнее в Windows. Если Codex уже установлен, повторная установка не нужна.

### Инструменты разработки

Установи **Node.js 24 LTS x64** и Git. На момент подготовки Node.js 24 указан как LTS на [официальной странице загрузки](https://nodejs.org/en/download).

Открой PowerShell и выполни:

```powershell
winget install --id OpenJS.NodeJS.LTS --exact --source winget
winget install --id Git.Git --exact --source winget
```

Если winget недоступен, установи Node.js 24 LTS Windows x64 через официальный MSI с nodejs.org, а Git — через [официальную страницу Git for Windows](https://git-scm.com/downloads/win). Версию Node.js проверь: для одинаковой среды здесь используем ветку 24.

После установки закрой и заново открой PowerShell и Codex, чтобы обновился PATH. Проверь:

```powershell
node --version
npm.cmd --version
git --version
node -p "process.platform + ' ' + process.arch"
```

Ожидается Node.js `v24.x`, последняя команда — `win32 x64`.

`npm.cmd` используется намеренно: если PowerShell блокирует `npm.ps1`, `.cmd` позволяет вызвать npm без изменения execution policy. Для текущей Posta не нужно заранее устанавливать Python, .NET, Docker, PostgreSQL, Rust, сервер Linux или Visual Studio Build Tools. Если конкретная будущая зависимость потребует дополнительные инструменты, разбирать это следует по её ошибке.

Posta не использует OpenAI API, поэтому API-ключ для приложения не нужен. Доступ к самому Codex настраивается отдельно входом в аккаунт.

## 4. Распаковать исходники в рабочую папку

Рекомендуемое место — **`C:\Dev\Posta`**, вне OneDrive и сетевых папок.

Предположим, комплект распакован в:

```text
C:\Users\ТВОЙ_ПОЛЬЗОВАТЕЛЬ\Downloads\Posta-Windows-Transfer-2026-10-22
```

В PowerShell:

```powershell
$postaTransfer = Join-Path $env:USERPROFILE 'Downloads\Posta-Windows-Transfer-2026-10-22'
New-Item -ItemType Directory -Force -Path 'C:\Dev' | Out-Null
Expand-Archive -LiteralPath (Join-Path $postaTransfer 'Posta-source-0.2.0-2026-10-22.zip') -DestinationPath 'C:\Dev'
Set-Location 'C:\Dev\Posta'
Get-ChildItem
```

Если комплект лежит в другом месте, замени значение `$postaTransfer`. Если `C:\Dev\Posta` уже существует, используй другую чистую папку; не распаковывай архив поверх чужой работы.

Правильный корень проекта содержит **`package.json`, `package-lock.json`, `AGENTS.md`, `src`, `electron`, `shared`, `tests`**. Иногда Проводник создаёт лишнюю внешнюю папку: в Codex нужно выбрать именно каталог, где лежит `package.json`.

Это самостоятельный снимок `apps/posta` из LumaHub. На ПК путь `apps/posta` больше не нужен: рабочий корень теперь `C:\Dev\Posta`. Ссылки на старые абсолютные пути Mac в прежнем чате использовать не следует.

## 5. Проверить запуск из исходников

В новой PowerShell из `C:\Dev\Posta`:

```powershell
npm.cmd ci
npm.cmd test
npm.cmd start
```

Что происходит:

- `ci` ставит версии из lockfile и скачивает Electron под Windows; нужен доступ к npm и загрузкам Electron.
- `test` запускает 19 тестов, включая SMTP-сервер только на `127.0.0.1`. Он не отправляет письма настоящим получателям.
- `start` сначала собирает интерфейс, затем запускает настоящий Electron-клиент.

Не копируй `node_modules` или Electron с Mac. Windows-зависимости устанавливаются заново. Во время разработки полностью закрывай Posta через трей перед следующим запуском: иначе защита от второго экземпляра может показать старое окно.

Команды на будущее:

| Команда | Назначение |
|---|---|
| `npm.cmd test` | Тесты |
| `npm.cmd run build` | Сборка интерфейса без запуска |
| `npm.cmd start` | Обычный Electron-клиент |
| `npm.cmd run demo` | Явная тестовая демонстрация с вымышленными ящиками |
| `npm.cmd run dev` | Только браузерный Vite-предпросмотр; не полноценный почтовый клиент |
| `npm.cmd run dist:win` | Установщик NSIS и переносимый ZIP для Windows x64 |

Успешный `test` не подтверждает авторизацию у реальных провайдеров: её нужно проверить на ПК, вводя пароли вручную в приложении.

## 8. Что ещё не готово: Exchange и ограничения

**Следующая задача — корпоративный Exchange с Autodiscover.** Пользователь подключался в Apple Mail простым вводом email и пароля; адрес сервера отдельно не вводил. На Mac в доступном окне настроек была включена автонастройка. Рабочий адрес сервера и допустимый протокол не установлены. Пароль не извлекался.

В 0.2.0 нет реализации Autodiscover, EWS, NTLM/Kerberos или корпоративного SSO. Поле Microsoft 365 работает через облачный IMAP/OAuth, а не через произвольный корпоративный Exchange. Нельзя обещать, что один только поиск сервера обеспечит авторизацию: после обнаружения потребуются поддерживаемые сервером протокол и способ входа. Исследовать это нужно на ПК с доступом к корпоративной сети/VPN, если она нужна.

Следующий Codex должен учитывать:

- Не подставлять угаданный адрес и не считать Exchange готовым без проверки.
- Не записывать корпоративный логин и реальные письма в исходники или тесты.
- Не отправлять пароль автоматически по непроверенной цепочке Autodiscover-redirect.
- Успешная компиляция и mock-тесты не равны успешному входу в реальный Exchange.

Прочие ограничения: Gmail OAuth отсутствует; поиск и смарт-ящики видят загруженную часть истории; из папки сначала загружаются последние 300 писем, дальше — порциями. Полноценного rich-text редактора, расписания отправки, автозапуска Windows, создания/переименования серверных папок и окончательного удаления писем нет. Черновики «на ПК» не синхронизируются с серверными черновиками. AI не нужен пользователю.

6. Ответы/пересылка, вложения, локальный черновик с восстановлением после перезапуска.
7. Только по ручной команде пользователя: отправка на свой проверочный адрес, скрытая копия и единственная копия в отправленных.
8. Отключение/возврат сети, чтение кэша, переподключение.

## 11. Типовые проблемы

- **`node`/`git` не найдены:** перезапусти терминал и Codex после установки, проверь PATH.
- **`npm.ps1 ... running scripts is disabled`:** вызывай `npm.cmd`, без смены системной политики.
- **Electron не скачался:** проверь сеть, прокси/VPN и доступность официальных загрузок; затем `node node_modules/electron/install.js` и повтори запуск. Не отключай TLS-проверки.
- **Не найдена platform binding Vite/Rolldown:** проверь `win32 x64`, убери только сгенерированный `node_modules` этой рабочей копии и повтори `npm.cmd ci`. Mac-зависимости не переносить, lockfile без причины не удалять.
- **Открывается прежнее окно:** приложение осталось в трее; заверши его и повтори запуск. Установленный клиент и dev-клиент используют обычное хранилище Posta, поэтому не запускай их одновременно для работы с одними аккаунтами.
- **`npm run dev` показывает только интерфейс:** ожидаемо; для аккаунтов нужен Electron через `npm.cmd start`.
- **Письма/папки не все:** проверь выбранный ящик, фильтр, сеть и дозагрузку истории. Смарт-ящик имеет кнопку обновления всех папок.
- **Ошибка входа:** проверь пароль приложения и разрешение IMAP, а не только обычный пароль аккаунта. Для корпоративного Exchange нужна отдельная реализация.

Локальные данные Windows обычно лежат в `%APPDATA%\posta`; секреты шифруются DPAPI. Кэш писем сам по себе не зашифрован приложением. Изменения кода не должны удалять этот каталог.
