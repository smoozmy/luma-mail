# Posta: инструкции для продолжения разработки

Начать с `docs/WINDOWS_HANDOFF.md`, затем прочитать `README.md`, `package.json` и `docs/windows-checklist.md`.

- Это самостоятельный личный клиент для Windows 11 x64: Electron + React/Vite, IMAP/SMTP и Exchange EWS/OWA. Production LumaHub, серверы, БД, DNS и SSH для него не нужны.
- Отдельный архив переносит текущие исходники, а не историю Git. Не считать, что они уже опубликованы в удалённом репозитории.
- В обычном режиме не показывать аккаунты, письма и папки, пока аккаунты не подключены. Демонстрация — только явный dev-режим.
- Сохранять светлый интерфейс по образцу Apple Mail, серверные папки и настраиваемые смарт-ящики.
- Корпоративный Exchange и Autodiscover реализованы в `electron/exchange.cjs` через EWS/HTTPS и NTLM; пользователь вводит только email и пароль. Не объявлять поддержку полностью проверенной без ручного подключения к рабочему серверу и проверки его папок/отправки.
- Не запрашивать пароли в чате и не добавлять реальные email, письма, токены, `.env`, локальный userData или ключи в исходники, логи, тестовые фикстуры и Git. Секреты хранить через OS safeStorage.
- Не извлекать пароли из Apple Mail/Keychain. Не ослаблять TLS, CSP, sandbox, contextIsolation или проверку IPC ради подключения почты. При Autodiscover не пересылать пароль на непроверенные перенаправления.
- Не отправлять реальные письма при автоматических тестах. Для этого есть локальный тестовый SMTP-сервер. Отправка на реальный адрес — только по явному поручению пользователя с указанным получателем и назначением.
- Сохранять изоляцию UID/UIDVALIDITY по папкам. SMTP-успех нельзя превращать в ошибку повторной отправки, если последующий APPEND в «Отправленные» не удался. Bcc не раскрывать в заголовках.
- Личные данные на Windows обычно находятся в `%APPDATA%/posta`, вне проекта. При обновлениях не удалять их; секреты macOS нельзя просто перенести на Windows.
- На Windows использовать Node.js 24 LTS x64, PowerShell и при необходимости `npm.cmd`, чтобы не менять execution policy. Зависимости устанавливать `npm.cmd ci` по lockfile.
- После изменений запускать соответствующие тесты и `npm.cmd run build`; для релиза `npm.cmd run dist:win`. Текущая версия 0.3.0 имеет 26 тестов. Фиксировать, что проверено на настоящей Windows/почте, а что только на mock/local SMTP.
- Обновлять документацию по изменённой функции. Не коммитить и не публиковать без поручения пользователя.
