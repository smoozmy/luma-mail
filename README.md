# Luma Почта

Личный почтовый клиент для Windows 11 x64. Светлый трёхколоночный интерфейс по образцу Apple Mail: список аккаунтов, общие входящие, список писем и область чтения. Приложение работает напрямую с почтовыми серверами, без backend LumaHub.

## Запуск на Windows

1. Скопируйте установщик из каталога `release` на компьютер и установите приложение. Если используете ZIP, распакуйте **весь** архив и запустите `Posta.exe` из распакованной папки.
2. Нажмите «Добавить учётную запись». Введите адрес и **пароль приложения**, созданный у почтового провайдера. Основной пароль аккаунта для iCloud, Google и Яндекса не подходит.
3. Добавьте остальные ящики. «Все входящие» объединяет их; отдельные «Входящие» в боковой панели показывают выбранный аккаунт.

Сборка личная, без сертификата подписи. Windows может показать сведения о неизвестном издателе. Программа рассчитана на Windows 11 x64; ARM64-сборка отдельно не проверялась.

### iCloud

Создайте пароль приложения на [account.apple.com](https://account.apple.com/) → «Вход в учётную запись и безопасность» → «Пароли приложений». Нужна двухфакторная аутентификация. Введите адрес почты iCloud; при использовании собственного домена и ошибке входа используйте основной адрес iCloud, связанный с этим ящиком. Сервер: `imap.mail.me.com:993`, TLS.

[Инструкция Apple](https://support.apple.com/en-gb/102525).

### Gmail

Включите двухэтапную аутентификацию и создайте [пароль приложения Google](https://myaccount.google.com/apppasswords). Введите полный адрес Gmail и полученный пароль. Сервер: `imap.gmail.com:993`, TLS. Обычный пароль Google не поддерживается. В этой версии входа через Google OAuth нет; в аккаунтах с Advanced Protection, некоторыми настройками 2FA или ограничениями Workspace пароль приложения может быть недоступен.

[Инструкция Google](https://support.google.com/accounts/answer/185833).

### Яндекс

В настройках Яндекс Почты разрешите почтовым клиентам доступ по IMAP. В [Яндекс ID](https://id.yandex.ru/security/app-passwords) создайте пароль приложения типа «Почта». Используйте полный адрес и этот пароль. Сервер: `imap.yandex.ru:993`, TLS.

[Инструкция Яндекса](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others).

### Microsoft 365 / Outlook.com

Поддержан Exchange Online через IMAP + OAuth device code; это не EWS и не поддержка произвольного локального Exchange Server.

Нужна собственная регистрация приложения Microsoft Entra:

1. В App registrations зарегистрируйте приложение. Для Outlook.com и Microsoft 365 выберите поддержку организационных и личных аккаунтов Microsoft.
2. Authentication → Advanced settings → Allow public client flows → Yes.
3. В API permissions добавьте delegated-разрешение Office 365 Exchange Online `IMAP.AccessAsUser.All` и `SMTP.Send`. Не создавайте client secret.
4. Скопируйте Application (client) ID в форму Posta.
5. Введите адрес ящика, нажмите «Подключить», затем откройте предложенную страницу Microsoft и введите показанный код. Подтвердите вход в нужную учётную запись.

Для отправки Microsoft аккаунты, подключённые в 0.1.0, нужно подключить заново с разрешением SMTP.Send. IMAP и SMTP AUTH (OAuth) должны быть разрешены для почтового ящика; администратор организации может потребовать согласование или блокировать этот способ входа. Входящие: `outlook.office365.com:993`, исходящие: `smtp.office365.com:587` с обязательным STARTTLS. Встроенного общего Microsoft client ID в сборке нет.

[Microsoft: OAuth для IMAP](https://learn.microsoft.com/en-us/exchange/client-developer/legacy-protocols/how-to-authenticate-an-imap-pop-smtp-application-by-using-oauth), [Device code flow](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code).

### Корпоративный Exchange / OWA

Поддержано подключение Exchange Server через Autodiscover и EWS по HTTPS с NTLM-аутентификацией. Это предназначено для рабочих ящиков, которые обычно открываются через Outlook Web Access (OWA), в том числе при доступе через корпоративную сеть или VPN. IMAP для этого сценария не требуется.

1. Выберите «Exchange / OWA» в форме добавления аккаунта.
2. Введите рабочий email и пароль рабочей учётной записи. Luma автоматически ищет `autodiscover.<домен>` и стандартные EWS-адреса на домене ящика.
3. Убедитесь, что компьютер подключён к корпоративной сети/VPN и администратор разрешил EWS. Сервер должен отдавать EWS по HTTPS и принимать NTLM; SSO-only или формы OWA без EWS этим способом не подключаются.

Luma получает папки и письма через EWS, открывает MIME-содержимое с HTML и вложениями, синхронизирует прочитанность и флажки, перемещение и очистку специальных папок, а отправку выполняет через EWS с сохранением копии в «Отправленных». Пароль передаётся только во время подключения и хранится локально через Electron safeStorage. Перенаправления Autodiscover на другой домен отклоняются.

## Возможности

- Несколько аккаунтов каждого провайдера и единые входящие.
- Получение новых писем через IMAP IDLE; периодическое обновление раз в минуту и переподключение.
- Первые 300 последних писем из каждой открытой серверной папки; «Загрузить более ранние письма» добавляет по 300.
- Предзагрузка содержимого до 20 небольших писем за синхронизацию, остальное загружается по открытию. Кэшированные письма доступны без сети.
- Локальный поиск по отправителю, адресатам, теме и загруженному тексту. Серверного полнотекстового поиска по всей истории нет.
- Непрочитанные, флажки и пользовательские смарт-ящики; изменение прочитанности и флажка синхронизируется с сервером.
- Группировка по заголовкам переписки; выбор отдельных писем разговора.
- HTML и обычный текст, встроенные MIME-изображения, сохранение вложений через системный диалог.
- Внешние изображения в открытых письмах загружаются автоматически; опасные схемы и скрипты остаются заблокированы.
- Уведомления Windows; закрытие окна оставляет приложение в трее. Через меню трея → «Завершить» можно полностью выйти.
- Изменение ширины списка перетягиванием разделителя, сворачивание боковой панели, Ctrl+F, Ctrl+R, стрелки вверх/вниз.
- При первом запуске нет вымышленных аккаунтов или писем. Аккаунты появляются только после успешного подключения.
- Серверные папки: Входящие, Отправленные, Спам, Удалённые, Черновики, Архив и пользовательские. Для IMAP назначение определяется по SPECIAL-USE; для Exchange используются специальные папки EWS и найденные серверные папки.
- Перемещение писем между папками, в спам и удалённые. Корзина не очищается автоматически, окончательное удаление не реализовано.
- Настраиваемые смарт-ящики: имя, режим «все»/«любое», условия по отправителю, получателю, теме, тексту, аккаунту, папке, дате, прочитанности, флажку и вложениям. Отдельные переключатели включения спама, удалённых и отправленных. Настройки сохраняются на этом ПК.
- Создание писем, ответ, ответ всем, пересылка с вложениями. Кому/Копия/Скрытая копия, несколько адресов через запятую. Скрытая копия входит в SMTP envelope, но не раскрывается в заголовках получателям.
- Вложения исходящего письма: до 30 файлов суммарно до 25 МБ. Обычный текст без HTML-редактора. Отправитель — адрес подключённого аккаунта.
- Автосохранение локальных черновиков и вложений; возобновление через «Черновики на ПК». Это отдельное хранилище, не синхронизирующее черновики с сервером.
- SMTP требует TLS: iCloud `smtp.mail.me.com:587` с обязательным STARTTLS, Gmail `smtp.gmail.com:465`, Яндекс `smtp.yandex.ru:465`. Пароль приложения тот же, что для IMAP.
- После подтверждения SMTP сохраняется копия в серверных «Отправленных»; Gmail делает это автоматически, поэтому второй APPEND для Gmail не выполняется. Если отправка успешна, но сохранение копии не удалось, приложение показывает предупреждение и не предлагает повторять доставку.
- Демонстрация доступна только разработчику через `npm run demo`. В установленном приложении она выключена.

Создание/переименование самих серверных папок, окончательное удаление писем, расписание отправки и AI в эту версию не входят. Смарт-ящики работают по загруженной части почты: для включения других папок откройте их либо нажмите «Обновить все папки» в смарт-ящике. История старше загруженных 300 писем добавляется отдельно при открытии каждой папки. Получение работает, пока приложение запущено, включая трей; Windows-служба и автозапуск в этой версии не настроены. Письма больше 40 МБ открываются через веб-почту; в Posta для них показывается объяснение. Exchange-серверы с отключённым EWS, только OAuth/Negotiate или нестандартным NTLM-доменом могут потребовать отдельной настройки.

## Локальные данные

Пароли приложений и OAuth-токены шифруются Electron safeStorage (Windows DPAPI) и не передаются в интерфейс. Письма, адреса и вложения в локальном кэше не шифруются самим приложением. Файлы находятся в каталоге userData Electron, обычно `%APPDATA%/posta`. Не добавляйте этот каталог в репозиторий. При отключении аккаунта удаляется его текущий кэш на этом ПК, письма на сервере сохраняются. Перенос зашифрованных секретов между компьютерами не поддерживается.

Почтовый HTML очищается, отображается в sandbox iframe без JavaScript. У рендерера нет доступа к Node.js; IPC ограничен отдельными операциями. Входящие TLS-сертификаты проверяются; отключения проверки нет. Вложения сохраняются только по команде пользователя и автоматически не запускаются.

## Разработка и сборка

Нужны Node.js 22.12+ или 24+ и npm. На Windows используйте PowerShell:

```powershell
cd apps/posta
npm ci
npm test
npm start
```

`npm run demo` запускает отдельное демохранилище с вымышленными письмами. `npm run dev` поднимает браузерный предпросмотр Vite, в котором подключение аккаунтов недоступно.

```powershell
npm run dist:win
```

Готовые файлы появляются в `release/`. Сборка NSIS и ZIP также возможна на macOS; исполняемый файл Windows на macOS не запускается и нуждается в отдельной проверке на ПК. Исходники и lockfile входят в репозиторий, `node_modules`, сборки и личные данные — нет.

### Автообновления

Релизы публикуются в GitHub-репозитории
`https://github.com/smoozmy/luma-mail`. GitHub Actions запускается для тегов
вида `v0.4.1`, выполняет тесты, собирает Windows NSIS/ZIP и публикует GitHub
Release вместе с `latest.yml`. Установленная Luma Почта проверяет новые версии
при запуске и далее периодически; скачивание выполняется только после
подтверждения пользователя, установка — после перезапуска.

Для локальной сборки публикация отключена командой `--publish never`. Для
публикации создайте тег с версией из `package.json` и отправьте его в GitHub:

```powershell
git tag v0.4.1
git push origin v0.4.1
```

Не помещайте в репозиторий пароли, API-ключи, `%APPDATA%/posta`, `release`,
`dist` или `node_modules`.

## Проверено в текущей среде

26 автоматических тестов: SMTP-диалог на локальном тестовом сервере, скрытая копия, MIME вложения, сохранность черновика при ошибке, частичное отклонение получателей, подтверждённая доставка при ошибке копирования в «Отправленные», папки и изоляция одинаковых UID, перемещение в корзину, смарт-условия, обновление локального формата 0.1.0, очистка HTML, блокировка трекеров, проверка конфигурации, синхронизация и удаление UID, UIDVALIDITY, кэш MIME, read/flagged, повторные обновления, обработка разрыва связи, запрет незашифрованного хранения секретов и стабильные идентификаторы Exchange. Для IMAP используется управляемый тестовый клиент. EWS/NTLM проверен на синтаксис и XML-контракт локальными проверками; подключение к рабочей почте и отправка реальных писем автоматизированно не выполнялись. Входы в реальные аккаунты, доставка уведомлений Windows и запуск на Windows требуют ручной проверки на пользовательском ПК.

## Обновление с 0.1.0

Установите новую версию поверх старой, предварительно завершив Luma Почту через трей. Аккаунты, зашифрованные секреты и кэш остаются в том же каталоге userData. При загрузке старые сообщения получают папку INBOX; добавляются пустые списки папок, смарт-ящиков и локальных черновиков. Производственная БД LumaHub не меняется. Для добавления рабочего Exchange/OWA аккаунта используйте отдельный тип «Exchange / OWA»; старый IMAP/OAuth аккаунт Microsoft 365 продолжает работать как прежде.
